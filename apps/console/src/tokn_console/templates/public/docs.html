Docs

Everything below is true of the running service. Where a feature is not built yet, it says so.

Base URL and key

Point any OpenAI-compatible client at https://{{ domain }}/v1 and use a key from the console as the bearer token.

$export OPENAI_BASE_URL=https://{{ domain }}/v1
$export OPENAI_API_KEY=tokn_live_…

Endpoints

  • POST /v1/chat/completions — OpenAI protocol, streaming and non-streaming.
  • POST /v1/messages — Anthropic protocol, streaming.
  • GET /v1/models — the models enabled for your account.

Errors

  • 401 — the key is missing, malformed, revoked, expired or over its cap.
  • 402 — your wallet cannot cover the request. Top up to continue.
  • 403 — the key lacks the scope, or is not allowed from this address.
  • 429 — rate limit or concurrency cap. The response carries Retry-After.
  • 502 — the upstream failed before responding. Nothing was charged.

What a request does

The worst case is reserved from your wallet, the request is forwarded, the answer is streamed back as it arrives, and the real cost is charged from the provider's own token counts. The unused hold is released. Every request produces one receipt.

BYOK

Bring-your-own-key is planned. It is not available yet, and this page will say so until it is.

Security

Keys are stored as HMAC-SHA256 hashes and shown once. Prompts and completions are never stored. Sessions are server-side, rotated on login, and expire after thirty minutes of inactivity. See privacy.
