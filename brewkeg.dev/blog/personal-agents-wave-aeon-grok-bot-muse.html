Three labs are about to ship always on AI agents at the same time

SpaceXAI shipped Grok Bot in August, Meta shipped Muse in early September, and OpenAI's Aeon is rumored for before DevDay on September 29. The product category is real, the billing math is different, and brewkeg has to think about what this means for the gateway surface.

2026-09-22·#agents#openai#aeon#grok-bot#muse#billing

There is a product category forming in real time, and almost nobody is talking about the most interesting thing about it.

In the last six weeks, three labs have shipped or announced always on personal AI agents:

  • SpaceXAI shipped Grok Bot on August 11
  • Meta shipped Muse on September 8
  • OpenAI's Aeon is rumored for before DevDay on September 29, possibly this week

Cognition is expected to ship its own agent platform in the same window. Anthropic is rumored to be close behind. By the end of October, the personal agent market will have at least five serious entries from five different labs, all trying to define the same product: a persistent AI teammate that lives in your accounts, takes actions on your behalf, and only checks in with you when it needs approval.

The interesting question is not which one wins. The interesting question is what happens to the billing math when the buyer of inference is no longer a human typing into a chat box.

What these products actually are

Strip away the marketing and all three products are doing roughly the same thing:

  • A persistent agent process that runs in the background, not tied to a chat session
  • A set of integrations to the apps you already use, with login and permission flows that look more like a human employee onboarding than an API integration
  • A cloud computer per agent, so the agent has somewhere to run code, browse, and execute multi step tasks without round tripping through the user's laptop
  • A escalation model where the agent only pings you when it hits a decision it cannot make on its own

The pitch is the same in every launch deck: stop using AI to answer questions, start using AI to do work. The differentiator is which integrations ship first, how aggressive the autonomy model is, and how the pricing works.

What changes about inference billing when the buyer is an agent

This is the part almost nobody is talking about.

In the chat era, the human is the buyer of inference. A human types a prompt, waits for a response, reads it, types the next prompt. The token consumption is roughly proportional to the human's attention budget. The user has direct feedback on whether the model is good, and they stop using it if it gets expensive.

In the agent era, the agent is the buyer of inference. The agent decides what to think about, how long to think, which tools to call, how many sub agents to spawn, and when to give up. The token consumption is proportional to the difficulty of the task and the quality of the agent's planning. The user does not see most of the inference. They see the final result and the bill.

This has three practical consequences for anyone running inference at scale:

  1. Token consumption per task is much higher than chat. A reasonable agent task might involve 50 to 500 model calls in the background before the user sees a single answer. If each call averages 2000 tokens, that is 100,000 to a million tokens per user visible action.

  2. Latency matters less than throughput. The user does not care if the agent takes 30 seconds to do a job, as long as the job gets done correctly. Throughput (tokens per second across many parallel calls) matters more than time to first token.

  3. Cost predictability gets harder. A chat user has a roughly fixed cost per session. An agent user has a cost that varies by task complexity, model choice, retry behavior, and how aggressive the autonomy model is. The variance per user can be 10 times or more.

For a metering gateway like brewkeg, this changes the surface we have to expose. We have to show developers not just "how many tokens did this call cost" but "how many tokens did this agent session cost across all of its sub calls, broken down by model and by which calls the agent made versus which calls were user driven."

What we are building for this

The brewkeg proxy already records per call usage to the database. The change for the agent era is that we have to expose session level rollups. A developer building an agent product should be able to ask the proxy "what did this agent session cost" and get a structured answer, not "sum the rows in your own usage table."

We are also going to add per agent budgeting. The current quota model is per user, per month. That is the right model for chat. For agents, we want per agent session caps that fail fast when an agent gets into a loop or a runaway cost pattern, before the user gets a surprise bill at the end of the day.

The first version of session level rollups ships with brewkeg in the next two weeks. If you are building an agent product and you want early access to the session cost API, mail us at hello at brewkeg dot dev with what you are building.

How to think about which agent platform to bet on

If you are a developer trying to decide which of these products to integrate with, the framework is straightforward:

  • Pick the platform whose integrations cover the apps your users actually live in
  • Pick the platform whose autonomy model matches the risk profile of the actions you would let it take
  • Pick the platform whose per task cost is predictable enough that you can ship a product with a sustainable margin

For most products in 2026, that means starting with the platform that has the best integrations in your specific vertical, not the one with the best marketing. The Muse launch, for example, is going to lean heavily on Meta's existing graph and identity surface. That makes it a strong default for products where the user identity story already runs through Facebook or Instagram. The Aeon launch from OpenAI is going to lean on ChatGPT's existing login surface. That makes it a strong default for products where the user is already a ChatGPT subscriber.

Grok Bot's positioning is different. SpaceXAI has been more aggressive about the autonomy model than either Meta or OpenAI. If you are building a product that needs an agent that will do things without checking in, Grok Bot is worth looking at hard. If you are building a product where the agent needs to be cautious and check in frequently, look at Muse first.

The brewkeg angle is that we will route to whichever backend makes sense for the workload, with the same metering and the same Naira billing regardless of which agent platform is upstream. Pick the agent based on what it can do for your users. We handle the inference cost.
