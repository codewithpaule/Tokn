OpenAI quietly removed Ultrafast from gpt 5.6 sol in Codex. That is not nothing.

The fastest tier in the Codex picker vanished this week, on the eve of DevDay. The most plausible read is that GPT 6 Sol ships with Ultrafast as the default, and 750 tokens a second becomes the new normal.

2026-09-22·#openai#gpt-6-sol#codex#ultrafast#latency

If you only follow the model announcements, you probably missed the more interesting thing that happened this week.

OpenAI removed the Ultrafast service tier from the gpt 5.6 sol entry inside Codex. The removed row literally described itself as "the fastest available responses for latency sensitive work." The tier is still live on OpenAI's API side. It just disappeared from the Codex picker.

That is a small change in a code path almost nobody reads. It is also exactly the kind of change that gets made in the 48 hours before a flagship launches, and it is worth understanding what it implies.

What Ultrafast actually does

Ultrafast is OpenAI's lowest latency tier for GPT 5.6 Sol. It runs the model on Cerebras hardware instead of the standard GPU fleet, which gets you up to 750 output tokens a second and a roughly 14 times speedup over the standard tier for the same model. The trade off is price: Cerebras inference is more expensive per token than the standard tier, and not every workload benefits from it.

For the workloads it is good for, it is very good. Real time code completion. Inline AI suggestions in editors. Conversational agents that need to keep up with a human typing speed. Anywhere you are paying the latency tax of waiting for a model to finish a sentence, Ultrafast is the answer.

For workloads where latency does not matter, like batch summarization or offline evaluation, Ultrafast is the wrong tool. You pay the premium for speed you never use.

Why pulling it from Codex matters

Codex is the developer facing surface for OpenAI's coding tooling. The picker is what developers see when they choose which model to run their agent through. Removing Ultrafast from gpt 5.6 sol in Codex does not mean Ultrafast is gone. It means OpenAI does not want developers associating the Ultrafast brand with the old model.

The most plausible read: GPT 6 Sol ships with Ultrafast as the default positioning. If you launch a new flagship, you do not want the marketing moment to be split between "new model" and "new tier." You want the new flagship to be the tier. 750 tokens a second on the new model is the headline.

A second plausible read: OpenAI is going to retire gpt 5.6 sol shortly after DevDay and did not want developers starting new Ultrafast workloads against a model that is about to be deprecated. The pull was a quiet deprecation signal.

Either read points the same direction: GPT 6 Sol is launching with sub second time to first token and high hundreds of tokens a second throughput as the headline performance number, not as an opt in tier.

What this means if you are routing through brewkeg

If you are using the standard OpenAI tier today, nothing changes. Standard tier pricing and latency on gpt 5.6 sol stays the same until the model is actually retired.

If you are using Ultrafast through brewkeg, your existing routes keep working through the API. The Codex UI change does not affect what we can route to. But you should expect the old Ultrafast endpoint to be deprecated within a few weeks of GPT 6 Sol shipping. We will post a deprecation notice the day OpenAI officially announces it.

If you are building a product where latency matters and you have been holding off on using Ultrafast because the tier felt experimental, this is the signal that the experimental phase is over. The tier is going mainstream. Plan for it.

How to think about Cerebras speed for real workloads

The 750 tokens a second number is impressive on paper. The honest answer for whether it actually helps your product depends on three things:

  1. How much of your latency budget is the model and how much is everything else. If your product spends 200 milliseconds on retrieval, prompt assembly, and network round trip before the first token, then going from 100 tokens a second to 750 tokens a second on the model only saves you a few hundred milliseconds on a multi thousand token response. That is real, but it is not the order of magnitude improvement it sounds like.

  2. Whether your workload is decode bound or prefill bound. Ultrafast is a decode speedup. If you are sending long prompts and waiting for the first token, the speedup is smaller than the marketing number suggests.

  3. Whether your users actually notice. Most user facing AI products do not benefit from sub second token streaming because the user interface is already gated on something else (network, rendering, user input rate). The workloads where 750 tokens a second matters are the ones where the model is on the critical path of a real time interaction, like voice agents or live code completion.

For everything else, standard tier is the right answer. The price difference is real, and the latency improvement is mostly going to time you did not need to wait in the first place.

What we are watching

Three things in the next week:

  1. Whether GPT 6 Sol launches with Ultrafast included or as a separate opt in. The Codex change suggests included, but we will not know until the model is live.

  2. Whether Cerebras inference pricing changes when GPT 6 Sol ships. The current pricing reflects the cost of running GPT 5.6 Sol on Cerebras silicon. A new model might be cheaper or more expensive to run, and that flows straight through to the tier price.

  3. Whether Anthropic responds with an equivalent tier for Claude Opus 5.5. The Cerebras partnership is OpenAI specific right now, but the underlying inference hardware question applies to every flagship.

We will post an update here as soon as we have signal on any of the three. Subscribe via RSS if you want the data the day it lands.
