Pay flagship rates only when you need to.

A cheap model drafts every answer from your retrieved context, a judge checks the draft against that context, and the flagship rewrites only the failures. Most questions never reach it. That is the metered-infrastructure play: cheap capacity does the bulk work, flagship capacity bills only where it earns. Adapted from OpenRouter's JEV cascade recipe ↗, wired to brewkeg's endpoint.

How it works.

  1. Draft cheap. brewkeg-nano answers from your excerpts. If the excerpts don't cover the question, it says so.
  2. Verify everything. The judge returns supported / unsupported / declined with a confidence. Send at 0.8 or above.
  3. Escalate or hand off. A failed draft goes to brewkeg-ultra for one rewrite, verified again. A declined draft skips the flagship entirely and hands to a human — with the draft and both verdicts attached.

The module.

One file, no dependencies, Node 18+ or Bun. Set BREWKEG_API_KEY in your environment.

cascade.ts · setup
// cascade.ts — run with node 18+ or bun. No dependencies. const BASE_URL = "https://brewkeg.dev/v1"; const BREWKEG_API_KEY = process.env.BREWKEG_API_KEY ?? "bk_live_YOUR_API_KEY"; const DRAFT_MODEL = "brewkeg-nano"; // cheap — answers most questions const JUDGE_MODEL = "brewkeg-nano"; // cheap — checks every draft const ESCALATION_MODEL = "brewkeg-ultra"; // flagship — only the failures const ACCEPT_CONFIDENCE = 0.8; async function chat(model: string, messages: { role: string; content: string }[]) { const res = await fetch(`${BASE_URL}/chat/completions`, { method: "POST", headers: { authorization: `Bearer ${BREWKEG_API_KEY}`, "content-type": "application/json", }, body: JSON.stringify({ model, messages }), }); if (!res.ok) throw new Error(`brewkeg ${res.status}: ${await res.text()}`); const json = await res.json(); return json.choices[0].message.content as string; }
cascade.ts · draft + verify
async function draftAnswer(model: string, question: string, excerpts: string[]) { return chat(model, [ { role: "system", content: "Answer ONLY from the excerpts below. If they don't cover the question, say so plainly.", }, { role: "user", content: `Question: ${question}\n\nExcerpts:\n${excerpts.map((e, i) => `[${i + 1}] ${e}`).join("\n")}`, }, ]); } type Verdict = { verdict: "supported" | "unsupported" | "declined"; confidence: number; }; // The relevance clause matters: "supported" requires the answer to address // the customer question AND every claim to appear in the excerpts. Without // the first half, fluent off-topic answers pass the judge. const JUDGE_PROMPT = `You check whether a draft answer is grounded in the excerpts. Reply with ONLY a JSON object: {"verdict": "supported" | "unsupported" | "declined", "confidence": 0-1}. - supported: the answer addresses the customer question AND every claim in it appears in the excerpts. - unsupported: any claim is missing from, or contradicts, the excerpts. - declined: the excerpts don't cover the question at all.`; async function verifyAnswer(question: string, excerpts: string[], answer: string): Promise<Verdict> { const raw = await chat(JUDGE_MODEL, [ { role: "system", content: JUDGE_PROMPT }, { role: "user", content: `Customer question: ${question}\n\nExcerpts:\n${excerpts.join("\n")}\n\nDraft answer: ${answer}`, }, ]); try { const v = JSON.parse(raw); if (["supported", "unsupported", "declined"].includes(v.verdict) && typeof v.confidence === "number") return v; } catch { // Unparseable verdict = failed verification. Escalate, don't send. } return { verdict: "unsupported", confidence: 0 }; }
cascade.ts · cascade + call site
type CascadeResult = { route: "send" | "handoff"; model: string; answer: string; verdicts: Verdict[]; }; async function answerWithCascade(question: string, excerpts: string[]): Promise<CascadeResult> { const verdicts: Verdict[] = []; for (const model of [DRAFT_MODEL, ESCALATION_MODEL]) { const answer = await draftAnswer(model, question, excerpts); const verdict = await verifyAnswer(question, excerpts, answer); verdicts.push(verdict); if (verdict.verdict === "supported" && verdict.confidence >= ACCEPT_CONFIDENCE) { return { route: "send", model, answer, verdicts }; } // Declined hands off with NO flagship call — the excerpts don't cover // the question, so a rewrite would just be a more expensive guess. if (verdict.verdict === "declined") return { route: "handoff", model, answer, verdicts }; } return { route: "handoff", model: ESCALATION_MODEL, answer: "", verdicts }; } // At your call site: const r = await answerWithCascade("Does PAYG credit expire?", excerpts); if (r.route === "send") await reply(r.answer); else await createTicket({ draft: r.answer, verdicts: r.verdicts });

What it costs.

Assumes 2k input / 500 output tokens per answer, 3k / 150 for the judge, and a 5% escalation rate. Rates are the live catalog numbers for brewkeg-nano and brewkeg-ultra.

Per 1,000 questionsCost
Draft (brewkeg-nano)$0.720
Judge (brewkeg-nano)$0.600
Escalations, 5% (brewkeg-ultra)$0.675
Cascade total$2.00
Flagship on everything$13.50

About 15% of the all-flagship bill at these assumptions — and every sent answer passed verification, which the flagship alone doesn't give you. Measure your own escalation rate for a week, then redo this table with it.

When not to.

  • Streaming clients. A cascade finishes draft + judge before emitting a token. For coding agents and chat UIs, that kills time-to-first-token — send those straight to the model.
  • Ungrounded tasks. The judge can only check an answer against context you supply. Open-ended writing and code generation have nothing to verify against.
  • Noisy verdicts. If escalation climbs past ~15%, the judge is the problem, not the draft: raise the threshold first, then try a stronger judge before touching the draft model.
