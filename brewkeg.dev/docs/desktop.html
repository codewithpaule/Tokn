Route Claude Desktop through brewkeg.

Same Anthropic protocol your machine already speaks, your brewkeg PAYG credit, every model in one picker. No Anthropic account required.

Infrastructure, not a new tool: metered billing in kobo and cents, Paystack checkout in NGN or USD, credit that never expires.

Do not paste your API key into a chat

Your bk_live_… key is not a prompt. It belongs in the gateway settings panel — Step 3 is the only place it goes.

Quick start

  1. 1
    Enable Developer Mode
    Open Help → Troubleshooting → Enable Developer Mode.
    TEXT
    Help → Troubleshooting → Enable Developer Mode
  2. 2
    Open the inference panel
    Developer → Configure Third-Party Inference…
    TEXT
    Developer → Configure Third-Party Inference…
  3. 3
    Point it at brewkeg
    Connection = Gateway, credential = Static API key, base URL https://brewkeg.dev, auth scheme x-api-key, paste your bk_live_… key. Test → Apply.
    TEXT
    Gateway base URL: https://brewkeg.dev Auth scheme: x-api-key API key: bk_live_…
  4. 4
    Let tools reach the web (optional)
    Capabilities → Allowed egress hosts — add the hosts your tools need.
  5. 5
    Bring your MCP servers
    Run brewkeg setup — it copies your existing MCP servers into the gateway profile. Quit + reopen.
    BASH
    brewkeg setup

Prerequisites.

  • Claude Desktop installed — download.
  • A brewkeg API key. Mint one at brewkeg.dev/dashboard.

Bring your MCP servers.

The gateway app keeps its own config folder, so MCP servers from your regular Claude Desktop do not carry over on their own. brewkeg setup copies them for you — every server, never overwriting one you already set on the gateway side. Fully quit and reopen the app after, same as Step 4.

Two things that look broken but are not: the Organization tab under Directory → Plugins stays empty — only an organization admin can fill it. And you can still add plugin marketplaces yourself via Discover — that stays enabled on third-party connections.

Troubleshooting.

I pasted the key and Claude doesn’t understand it+
The key went into the chat instead of the settings panel. Close the conversation, then redo Step 3 — Developer → Configure Third-Party Inference… → Gateway API key. Click Apply Changes and fully quit + reopen the app.
“Test connection” fails+
Double-check the Gateway base URL is exactly https://brewkeg.dev with no trailing slash, and the auth scheme is x-api-key. Your key must start with bk_live_. If Test connection passes but requests still fail, click Apply Changes — Test connection reads unsaved fields.
Connection errors on every request+
Auth scheme set to x-api-key, not bearer — that is the header Claude Desktop's native Anthropic path sends. If you switched to bearer, put it back. Also confirm the key is not revoked on the API keys page.
No models appearing+
Ensure your brewkeg account has credit. Check /dashboard/billing — PAYG top-ups start at ₦5,000 and never expire.
“Continue with Gateway” not showing+
Make sure you clicked Apply Changes (not Save Changes) and fully quit + reopened Claude Desktop — Cmd+Q, not the red window dot. Older builds label the same thing “Local configuration”.
WebFetch blocked by the sandbox+
See Step 4. Developer → Configure Third-Party Inference… → Capabilities tab → Allowed egress hosts. Then Apply Changes and restart.
My MCP servers / plugins are gone on the gateway+
Run brewkeg setup again — it migrates your existing servers (Step 5), then fully quit + reopen. If the Organization tab is the empty one, that is expected: only an organization admin can provision it.
TLS errors running Claude Code inside Claude Desktop+

Claude Code runs in a sandbox whose network isolation can break TLS connections to the gateway. Relax it by adding the following to a Claude settings file, then restart Claude Desktop:

~/.claude/settings.json
{ "sandbox": { "enableWeakerNetworkIsolation": true } }

Prefer the narrowest scope that fixes your problem — ~/.claude/settings.json (%USERPROFILE%\.claude\settings.json on Windows) applies it to every project — open it with code ~/.claude/settings.json (code "%USERPROFILE%\.claude\settings.json" on Windows CMD, $env:USERPROFILE in PowerShell), while .claude/settings.json or .claude/settings.local.json in a project folder scopes it to that project. Remove the override once it’s no longer needed.

Verifying it works.

After the model picker populates, send one message. If the request lands on brewkeg you’ll see a fresh row in /dashboard/requests within a couple of seconds, with the input/output token counts and cache hits. If the row appears, you’re routing through brewkeg.

Stale or empty? Check the API keys page — the key you pasted must be active and not revoked.
